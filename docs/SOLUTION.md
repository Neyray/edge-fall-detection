# 端到端算法解决方案文档

**赛题**：面向低算力端侧平台基于视觉的实时跌倒检测（华为专项赛道）
**队伍**：Ray　**成员**：宗家锐（2024302141121）

---

## 一、问题分析与总体思路

居家养老 / 医疗照护场景要求跌倒检测**准确、实时、隐私安全**，且必须运行在算力/存储/功耗
受限的端侧 NPU 上。赛题给出的三大痛点与硬性红线如下：

- 动作语义混淆：跌倒与快速坐下、弯腰、躺下在**单帧视觉表征**上高度相似；
- 算力/效率瓶颈：3D-CNN、Video-Transformer 等重型时序网络时延过高；
- 长尾场景：微光、夜间红外、遮挡、视角变化导致轻量模型精度骤降。

**核心洞察**：跌倒的判别信息主要在**人体运动的时间演化**中，而非单帧像素纹理。
因此我们不在原始像素上做重型 3D 时序建模，而是先用轻量姿态网络把每帧压缩为
**17 点骨骼（17×3=51 维）** 这一极稀疏、且与光照/纹理/肤色/背景解耦的中间表征，
再在骨骼序列上做**廉价的时空图卷积**。这一"表征降维"是同时满足精度与端侧算力约束的关键。

### 总体架构（端到端纯视觉）

```
 相机(1080P+, 可见光/红外)
        │
        ▼
[阶段1] YOLO11n-Pose ── 逐帧检测框 + COCO-17 骨骼 + ByteTrack 多人跟踪
        │  (骨骼按检测框归一化到[-1,1]，消除位置/尺度/机位差异)
        ▼
   按 track_id 维护滑动窗口(30帧≈1s)
        │
        ├──────────────┐
        ▼              ▼
[阶段2] Lite ST-GCN   几何先验(躯干角/宽高比/质心下坠速度)
   时序跌倒概率          可解释兜底判据
        └──── 加权后融合(0.6 : 0.4) ────┐
                                        ▼
                    [后处理] 状态机 + 滑动投票
             NORMAL →(下坠)→ FALLING →(持续倒地≥1.5s)→ FALLEN(报警)
                                        ▼
                            本地实时报警(端侧闭环, 无云端上传)
```

## 二、各模块设计与选型

### 2.1 阶段1：轻量姿态估计（YOLO-Pose）
- **选型**：YOLO11n-Pose（~2.87M 参数，11.5MB）。单模型同时输出人体框与 17 关键点，
  单阶段、无 anchor、算子规整（Conv/SiLU/Concat），是海思 Ascend、瑞芯微 RKNN 等
  NPU 工具链一等公民，可直接量化为 INT8。
- **红外适配**：红外单通道统一复制为 3 通道灰度输入；姿态估计依赖轮廓/结构而非色彩，
  对红外/微光稳健。训练期用 `to_infrared_like` / `low_light` 合成红外与夜间样本微调。
- **多人**：内置 ByteTrack（`persist=True`）为每个人分配 track_id，天然支持多人同框。

### 2.2 阶段2：Lite ST-GCN 时序判别头
- **原理**：按 COCO-17 骨架构建图邻接矩阵，交替做**空间图卷积**（帧内按骨架聚合）与
  **时间卷积**（跨帧建模运动），4 个 ST-GCN block（通道 3→32→32→64→96），时间维两次
  下采样，全局池化后二分类。
- **参数**：仅 **0.158M**、fp32 0.63MB、单次 <2ms。远低于赛题预算，把 20M 额度主要留给姿态主干。
- **关键预处理**：关键点按检测框归一化，使模型对"人在画面何处、离相机多远、机位角度"不敏感，
  是跨场景泛化的基础。
- **NPU 备选**：若目标 NPU 对图卷积 einsum/gather 支持不佳，提供 `LiteTCN`（纯 1D 因果卷积，
  算子只含 Conv1d/BN/ReLU）作等价替换。

### 2.3 几何先验后融合
纯手工、零成本、可解释的三条判据，与 ST-GCN 概率按 0.6:0.4 融合：
- **躯干角**：肩→髋向量与竖直方向夹角，站立≈0°、倒地≈90°；
- **检测框宽高比**：站立 <1、倒地 >1；
- **质心竖直下坠速度**：对最近半秒质心 y 线性拟合斜率，按人体高度归一化。

作用：在骨骼点因遮挡/夜间噪声大、时序模型不确定时提供兜底，并抑制"弯腰/坐下"误报。

### 2.4 时序后处理：状态机 + 投票（降误报核心）
仅靠逐帧概率会抖动误报。引入跌倒事件状态机：
`NORMAL →(连续多帧高分)→ FALLING →(持续倒地 ≥1.5s)→ FALLEN(报警)`。
只有"**先发生下坠、之后长时间保持倒地**"才确认为真实跌倒——
快速坐下/弯腰会短暂高分但随即恢复站立，不满足"持续倒地"，因此被自动过滤。
起身持续若干帧后自动解除报警。

## 三、针对三大痛点的专属优化

1. **动作混淆** → 运动轨迹建模（ST-GCN）+ "下坠+持续倒地"状态机 + 几何躯干角；三重约束区分日常动作。
2. **端侧算力** → 骨骼中间表征把时序建模成本降到 <2ms；两阶段合计仅 3M 参数、12MB；提供 TCN/ONNX/INT8 部署路径。
3. **长尾泛化** → ①骨骼表征对光照/纹理解耦；②训练期红外/微光合成 + 关键点遮挡丢弃 + 左右镜像换视角 + 时间尺度缩放；③几何先验兜底。

## 四、创新点与先进性

- **表征层解耦**：以骨骼中间表征替代像素做时序推理，从根源上化解"红外/可见光跨域"与"端侧算力"两难，
  而非在像素域堆叠昂贵的域自适应模块。
- **判别 + 先验 + 事件 三级融合**：学习式（ST-GCN）、规则式（几何）、逻辑式（状态机）互补，
  在小样本长尾下比单一端到端网络更稳、更可解释、更易按场景调参。
- **预算极省**：3M 参数仅占 20M 红线 15%，为升级更强姿态主干或多任务预留空间；
  时序头 0.16M 可整模驻留 NPU SRAM。
- **红外零成本适配**：合成增强免采集，落地即用。

对比公开方案：LFD-YOLO / BMR-YOLO / YOLO-fall 均为**单阶段端到端检测**（把"跌倒"当一类目标），
优点是极简，但单帧判别对"坐下/弯腰"混淆与遮挡长尾较敏感、且缺乏显式时序与事件逻辑。
本方案以极小的第二阶段代价换取**显式时序建模 + 事件级降误报 + 跨域解耦**，在保持端侧实时的同时更贴合真实看护场景。

## 五、可行性与实测

已在 RTX 5070 Ti / torch2.11 环境端到端跑通（见 `tests/` 与 `scripts/benchmark.py`）：

| 指标 | 合计 | 红线 | 结论 |
|---|---|---|---|
| 参数量 | 3.03 M | ≤20 M | ✅ 15% |
| fp32 权重 | 12.1 MB | ≤80 MB | ✅ |
| 端到端时延(GPU 参考) | 9.3 ms | ≤100 ms | ✅ |
| 时序头 ONNX | 0.64 MB | NPU≤20MB | ✅ |

**评测协议**：按赛题以视频片段为单位统计。建议用**事件级**指标（每段是否正确报警/是否漏报误报）
配合逐帧召回，重点关注长尾子集（红外、遮挡、夜间）的召回与误报率。

## 六、端侧部署链路

1. `export_onnx.py` 导出两阶段 ONNX（opset12，算子规整）；
2. 海思：ONNX→ATC→`.om`，INT8 量化；瑞芯微：ONNX→RKNN-Toolkit→`.rknn`；
3. 板端流水线：VPU 解码 → NPU 跑 YOLO-Pose → CPU 轻量跑 ST-GCN/状态机（<2ms）→ 本地 GPIO/声光报警，视频流全程不出端，隐私闭环。
