# 真实数据处理与模型训练记录（初赛）

> 记录"从零拿到真实数据 → 训练模型 → 评测 → 端到端验证"的全过程：
> 挑了哪些数据、为什么这么挑、模型到底怎么训练的、每一步做了什么、结果如何。
> 供复现、扩量重跑与答辩问答使用。

---

## 一、起点与目标

- 代码框架已跑通，但**只有合成骨骼**（程序模拟的站立/跌倒），报告里的 accuracy=1.0 只能证明
  "链路能跑"，**不能当作真实检测效果**。
- 目标：补上**真实数据 + 真实指标**，并验证完整链路在原始视频上有效。

## 二、数据来源与选型

### 2.1 选定数据集

**Kaggle：`payutch/fall-video-dataset`**（CC0 许可，16 GB）。它同时提供原始视频和**逐帧
COCO-17 骨骼关键点 CSV**（`Fall/Keypoints_CSV/`、`No_Fall/Keypoints_CSV/`），共 **6988 段**。

### 2.2 为什么用"骨骼 CSV"而不是视频

- 骨骼正是本项目**阶段二（时序判别）的输入**。直接用数据集自带骨骼，可以
  **跳过下载 16 GB 视频、跳过跑 YOLO-Pose 抽骨骼**两步，快且省。
- 只打包骨骼 CSV 约 **297 MB**，视频那 ~15.9 GB 不用碰。
- 后续做端到端 demo 时，再单独下载了 16 段**视频**（约 30 MB）。

### 2.3 下载踩坑与最终办法

踩过的两个坑：

1. **路径靠截图猜、并不存在**：真实目录是 `Keypoints_CSV`，不是猜的 `Raw_Video/xxx.mp4`。
2. **Kaggle 单文件下载接口对该数据集整体失效**：`kaggle datasets download -f <单文件>` 一律
   返回 404——连清单里确实存在的文件也 404。逐文件下载这条路走不通。

最终可行办法（**Kaggle 在线 Notebook**）：Notebook 跑在 Kaggle 云端，16 GB 数据集已只读挂在
云端 `/kaggle/input/`。用几行代码在**云端**把所有 `.csv` 打包成 zip 写到 `/kaggle/working/`
（notebook 唯一可下载的输出区），本地只下这个 ~297 MB 的 zip。
即"**把计算搬到数据旁边，只带走结果**"。

## 三、挑了哪些数据、为什么这么挑

- **用哪一部分**：每类各取 **3000 段**（初赛先用 1500/类跑通，后借 GPU 扩到 3000/类重训，
  指标更稳、验证集更大更可信），不是全用 6988 段。
- **类别均衡**：跌倒视频短（中位 ~56 帧）→ 窗口少；日常视频长 → 窗口多，窗口级天然 ~1:3.3 不均衡。
  训练时**下采样多数类到 1:1**，否则模型会偏向"日常"、压低跌倒召回。
- **按片段（clip）划分**训练/验证：同一段视频切出的多个窗口**整体**分到 train 或 val，绝不跨集。
  否则相邻窗口高度相似、同时出现在训练和验证 → 指标虚高（数据泄漏）。

一句话：**均衡 + 防泄漏 + 适量**，让指标可信。最终划分：

| 划分 | 片段 | 窗口(均衡后) |
|---|---|---|
| 训练集 | 跌倒 2400 + 日常 2400 | 16632（fall 8316 / adl 8316） |
| 验证集 | 跌倒 600 + 日常 600 | 4188（fall 2094 / adl 2094） |

## 四、模型是怎么训练的

### 4.1 关键认知：三个阶段里，只有一个需要训练

很多人会以为"三阶段都要训练"，实际不是：

| 阶段 | 模块 | 参数量 | 是否训练 | 来源 |
|---|---|---|---|---|
| 阶段一 | YOLO11n-Pose（出人体框+17关键点） | 2.87 M | ❌ **不训练** | ultralytics 官方**预训练权重**，直接用 |
| 阶段二 | Lite ST-GCN（时序判别） | 0.158 M | ✅ **只训练这一段** | 我们用真实骨骼训练得到 |
| 阶段三 | 几何先验 + 状态机（降误报） | 0 | ❌ **零参数、零训练** | 纯规则，只有人工设定的阈值（超参） |

所以 `checkpoints/stgcn_fall.pt` 里**只有那 0.158 M 的时序头**，YOLO 权重是另一个独立文件
（`yolo11n-pose.pt`，官方预训练）。几何先验和状态机是代码里的判据与有限状态机，不含可学习参数。

### 4.2 训练的输入长什么样

`prepare_real.py` 把骨骼 CSV 切成固定长度窗口，每个样本是一个 `.npz`：

- `kp`：形状 `(30, 17, 3)` —— **30 帧 × 17 个关节 × (x, y, 置信度)**
- `label`：`0` = 日常，`1` = 跌倒

坐标是**逐帧按人体外接框归一化到 [-1,1]** 的（与 `src/pose/extractor.py::normalize_keypoints`
一致），目的是消除人在画面中的位置与远近差异，让模型跨机位、跨分辨率可用。
送进网络前 permute 成 `(3, 30, 17)`，即"通道×时间×关节"，batch 后为 `(B, 3, 30, 17)`。

### 4.3 训练配置（`scripts/train_temporal.py`）

| 项 | 值 |
|---|---|
| 优化器 | AdamW，lr `1e-3`，weight_decay `1e-4` |
| 学习率调度 | CosineAnnealingLR（按总 epoch 退火） |
| 损失 | CrossEntropy，**类别权重 [1.0, 1.5]**（跌倒类加权，偏向高召回——漏报比误报危险） |
| batch size | 64 |
| epochs | 18 |
| 设备 | CPU（模型仅 0.158 M，约 1.5–2.5 分钟跑完） |
| 数据增强 | 训练时开启骨骼域增强（时间缩放 `temporal_scale` + 关节扰动/丢弃 `augment_skeleton`） |
| 保存策略 | 按**验证集准确率**保存最佳权重 → `checkpoints/stgcn_fall.pt` |

权重文件内容：`{"model": state_dict, "acc": 最佳验证准确率, "window": 30}`。

### 4.4 完整"训练→使用"链路

```
Kaggle 骨骼 CSV
   └─(prepare_real.py: 选片 → 按片段划分 → 切30帧窗口 → 类别均衡)→ .npz 窗口
        └─(train_temporal.py: 只训练 Lite ST-GCN)→ checkpoints/stgcn_fall.pt
             ├─(evaluate_temporal.py)→ 窗口级指标
             ├─(ablation.py)→ 事件级消融（配合几何/状态机，均为规则）
             └─(demo_video.py)→ 端到端：YOLO-Pose(预训练) + 本模型 + 几何 + 状态机 跑真实视频
```

推理时 YOLO-Pose 负责"看图出骨骼"，训练好的 ST-GCN 负责"看骨骼序列判跌倒"，
几何先验与状态机在其后做融合与事件确认。**只有中间那一段是学出来的。**

## 五、处理流程（脚本与命令）

所有脚本在 `scripts/`，conda 环境 `yolo`。

| 步骤 | 脚本 | 作用 |
|---|---|---|
| ① 转换 | `csv2npz.py` | Kaggle 长表 CSV(`Frame,Keypoint,X,Y,Confidence`) → `(30,17,3)+label` 的 npz 窗口 |
| ② 选片+划分 | `prepare_real.py` | 每类选 N 段 → **按片段**划分 train/val（零泄漏）→ 各自转窗口 → **窗口级类别均衡**；输出验证片段清单 |
| ③ 训练 | `train_temporal.py` | 训练 Lite ST-GCN 时序头 → `checkpoints/stgcn_fall.pt` |
| ④ 窗口级评测 | `evaluate_temporal.py` | 验证集 accuracy/recall/precision/F1 → `reports/eval_real.json` |
| ⑤ 事件级消融 | `ablation.py` | 每段验证视频流式跑四种配置，判"整段是否报警" → `reports/ablation.json` |
| ⑥ 端到端 demo | `demo_video.py` | 对真实**视频**跑完整链路，叠加骨骼/状态/报警，输出标注 mp4 |

复现命令：

```bash
conda activate yolo
cd ~/projects/edge-fall-detectioin

# 解压 keypoints_only.zip 到 data/kaggle_csv 后：
python scripts/prepare_real.py --src data/kaggle_csv --per-class 3000 \
    --train data/skeletons/train --val data/skeletons/val \
    --val-list reports/val_clips.txt --window 30 --stride 15
python scripts/train_temporal.py --data data/skeletons/train --val data/skeletons/val --epochs 20
python scripts/evaluate_temporal.py --data data/skeletons/val --ckpt checkpoints/stgcn_fall.pt --out reports/eval_real.json
python scripts/ablation.py --val-list reports/val_clips.txt --ckpt checkpoints/stgcn_fall.pt \
    --out reports/ablation.json --lie-sweep 0.15,0.2,0.3,0.4

# 端到端 demo（限 4 线程避免 CPU 过热；纯推理，不训练）
python scripts/demo_video.py --videos data/demo_videos --out reports/demo \
    --ckpt checkpoints/stgcn_fall.pt --weights yolo11n-pose.pt --threads 4 --lie-seconds 0.2
```

## 六、结果

### 6.1 阶段二时序头（窗口级）

准确率 0.853 / 召回 0.843 / 精确 0.860 / F1 0.852（验证集 4188 窗口，来自 1200 段留出片段）。

### 6.2 事件级消融（以视频片段为单位）

| 配置 | 召回率 | 精确率 | 误报率 | F1 |
|---|---|---|---|---|
| 仅 ST-GCN | 0.988 | 0.616 | 0.615 | 0.759 |
| 仅 几何先验 | 0.843 | 0.804 | 0.205 | 0.823 |
| 融合（无状态机） | 0.977 | 0.818 | 0.217 | 0.890 |
| **融合 + 状态机（先下坠+倒地≥0.15s）** | 0.860 | 0.913 | **0.082** | **0.886** |
| 融合 + 状态机（先下坠+倒地≥0.4s） | 0.708 | 0.916 | **0.065** | 0.798 |

**结论**：几何融合把误报率 0.615→0.217（精确率 0.62→0.82）；状态机的「先下坠 + 持续倒地」
双重判据再降到 0.065–0.082，且几乎不损失召回。三级融合每个模块的价值都被独立验证。

### 6.3 端到端 Demo（完整链路在真实视频上）

另外下载真实**视频**跑完整流水线（YOLO-Pose → ST-GCN → 几何 → 状态机），CPU 限 4 线程。

**先做了训练集去重**：最初挑的 16 段里，`20240912_101626.mp4` 与 `B_D_0002.mp4` 经脚本比对
命中训练集，已剔除到 `data/demo_excluded_trainset/`。最终用 **14 段（7 跌倒 + 7 日常，
全部未参与训练）**，清单见 `reports/demo_clip_list.md`。

结果：**跌倒 6/7 报警、日常 0/7 误报**。标注视频在 `reports/demo/`，
截图在 `reports/demo_frames/`（跌倒→红色报警；躺床→绿色 NORMAL 不报警）。

> 样本量小，**仅用于证明完整链路跑通，不能当泛化结论**；泛化指标以 6.2 的 600 段消融为准。

踩坑：仓库里的 `yolo11n-pose.pt` 曾损坏（2.1 MB），删除后由 ultralytics 自动重下正确权重（6 MB）；
YOLO 跟踪还需 `pip install lap`。

## 七、如实说明（答辩需交代）

- 窗口级与消融指标用的是数据集**自带骨骼**，**未接入 YOLO-Pose、未加红外增强**，
  属于对**阶段二 + 后处理**的独立验证；端到端 demo 才是完整链路。
- **16 段 demo 的 7/8 与 1/8 样本量太小**，只适合证明"完整链路跑通"，
  **不能作为泛化性能结论**；可靠指标以 6.1/6.2 的 600 段留出集为准。
- 数据集片段是 ~2 秒的**跌倒事件短片**（跌倒片段中位 ~56 帧），故状态机"持续倒地"阈值按
  片段时长设为 0.15–0.4 s；部署到长时监控流时应设回 1.5 s。
- 阶段一 YOLO-Pose 使用官方预训练权重，**未在本数据集上微调**；红外/微光增强函数已实现但
  尚未接入训练，也**还没有红外子集指标**。

## 八、外部评审问题与修复记录

一次外部代码评审指出若干"宣传口径跑在实验证据前面"的问题，已逐条修复：

| # | 问题 | 修复 | 验证 |
|---|---|---|---|
| 1 | 状态机**并未真正强制"先下坠"**：第一次高分就能进 FALLING，静态躺卧也可能报警，与 PPT 说法不符 | `FallStateMachine` 增加下坠门控（`require_drop`/`drop_thr`/`drop_memory`），进入 FALLING 需**投票通过 且 近期检测到质心快速下坠**；`update()` 新增 `vy` 入参 | 构造用例：静躺(高分无下坠)→ `NORMAL` 不报警；下坠+倒地 → `FALLEN` 报警 ✅ |
| 2 | 多人跟踪漏洞：未获 track ID 的人**全被映射为 0**，骨骼历史串味；消失轨迹不清理 | 新增 `_assign_ids()` 就近匹配 + 合成 ID 分配；`_prune_tracks()` 按 `max_track_age` 超时清理 | 两个无 ID 的人分到独立轨迹 `10000/10001`，各自历史独立；超时后正确清空 ✅ |
| 3 | **真实帧率没传进检测器**：视频读了 FPS 但状态机仍按 30 计算 | 新增 `FallDetector.set_fps()`；`demo_video.py` / `run_demo.py` 每段视频用真实 FPS 重建状态 | 已接入两个演示脚本 ✅ |
| 4 | 缺权重时 `export_onnx.py` **静默导出随机初始化模型** | 缺权重直接报错退出，需显式 `--allow-random` 才导出（并打印醒目警告）；补 `pandas`/`lap`/`python-pptx` 进 `requirements.txt` | 缺权重时正确报错 ✅ |
| 5 | Demo 视频可能与训练集重叠 | 脚本精确比对，剔除命中训练集的 2 段，只用 14 段干净视频，并输出清单 | `reports/demo_clip_list.md` ✅ |

**修复带来的指标变化**（下坠门控生效后）：事件级误报率显著下降、精确率提升，召回基本持平——
**修复不仅让"先下坠"的说法成立，还实际提升了性能**。当前（3000/类大模型）最优档：
误报率 **0.082**、精确率 **0.913**、召回 **0.860**（见第六节表）。

**红外/微光/遮挡长尾指标已在 RTX 4090 上实测**（见下）；仍属**待验证**：NPU `.om/.rknn`
量化与板端时延、以及用合成红外数据微调 YOLO-Pose 后的召回回升。

## 九、长尾鲁棒性实测（RTX 4090）

对 **60 段未参与训练的留出视频**（`scripts/eval_longtail.py`），图像域施加退化后跑完整流水线：

| 条件 | 召回率 | 精确率 | 误报率 | +CLAHE 后召回 |
|---|---|---|---|---|
| 干净（可见光） | 0.800 | 0.960 | 0.033 | — |
| 类红外 | 0.600 | 0.900 | 0.067 | 0.567 |
| 微光/夜间 | 0.533 | 0.941 | 0.033 | 0.500 |
| 遮挡 | 0.267 | 0.889 | 0.033 | **0.433** |

**诚实结论**：误报率跨域全程稳定（0.033–0.067），说明判别逻辑（阶段二+三）鲁棒；
但召回随退化下降，瓶颈在**阶段一 YOLO-Pose 未做红外/微光微调**（增强函数已实现却未接入训练）。
零成本 CLAHE 预处理只在遮挡场景把召回从 0.267 拉回 0.433，对红外/微光基本无效。
结果文件：`reports/longtail.json`、`reports/longtail_clahe.json`。

### 9.2 域微调尝试（负结果，如实记录）

进一步在 GPU 上试了**域微调**：`build_ir_dataset.py` 用预训练 YOLO 在干净帧出伪标签、
把帧退化成类红外/微光作为训练图（伪标签自蒸馏），微调 YOLO-Pose 40 epoch，再重跑 60 段长尾。

| 条件 | 微调前召回 | 微调后召回 |
|---|---|---|
| 干净 | 0.800 | 0.633 ↓ |
| 类红外 | 0.600 | 0.667 ↑ |
| 微光 | 0.533 | 0.533 = |
| 遮挡 | 0.267 | 0.167 ↓ |

**净结果为负**，归因：① 伪标签来自"教师本就检得好"的样本，教不会难例；② 小数据 40 epoch
灾难性遗忘干净域；③ 遮挡与红外是不同问题，IR 增强对遮挡无帮助。**正确下一步**：真实红外
标注 + 冻结主干只训 pose 头 + 针对性遮挡增强。结果文件：`reports/longtail_ft.json`；
微调权重：`checkpoints/yolo11n-pose-ir.pt`（存档，**不作为正式部署权重**）。价值在于验证失败路径、定位原因。

### 9.1 这台 GPU 是怎么用起来的（云端 RTX 4090，AutoDL）

本项目训练/推理本身很轻（CPU 都够），GPU 只用于跑上面这批长尾实测（视频多、退化处理吃算力）。
完整流程如下，供复现：

1. **租实例**：AutoDL 选 RTX 4090 + 镜像 PyTorch 2.3 / Python 3.12 / CUDA 12.1，按量计费，用完即关。
2. **免密登录（不经手密码）**：本地生成 SSH 密钥后，用 `ssh-copy-id` 把公钥装到实例，之后全程免密：
   ```bash
   ssh-copy-id -p <端口> -i ~/.ssh/id_ed25519.pub root@<实例地址>
   ```
3. **上传代码（排除大数据）**：只传代码与权重，不传 686MB 的 CSV：
   ```bash
   rsync -az -e "ssh -p <端口>" --exclude data/ --exclude .git/ --exclude reports/demo/ \
       ./ root@<实例地址>:/root/autodl-tmp/edge-fall-detection/
   ```
4. **装依赖**（云镜像已带 torch/cuda）：
   ```bash
   pip install ultralytics lap pandas opencv-python-headless
   ```
5. **上传视频 → 跑实验**（`--device cuda`），后台运行防 SSH 断连：
   ```bash
   nohup python scripts/eval_longtail.py --videos data/longtail_videos --device cuda \
       --conditions clean,ir,lowlight,occlusion --out reports/longtail.json > /tmp/lt.log 2>&1 &
   ```
6. **拉回结果**：`scp -P <端口> root@<实例地址>:.../reports/longtail.json ./reports/`
7. **关机止损**：在 AutoDL 控制台关机（数据盘保留，下次开机代码/视频都在）。

> 说明：模型训练（`train_temporal.py`）本轮仍在本地 CPU 完成（模型仅 0.158M）；GPU 目前只承担
> 长尾推理评测。真正需要 GPU 训练的是**下一步用合成红外数据微调 YOLO-Pose**（尚未做）。
